# 外部接入指南

> 本文档指导外部系统安全、高效地调用本仓库提供的功能。

> 这是一个**本地 Markdown 文档查看器**，以 HTTP 服务形式运行在本地，提供文件读取、Markdown 渲染和文件夹加载能力。

---

## 1. 接入前准备

### 1.1 服务启动

本仓库以 Node.js 进程方式运行，启动命令：

```bash
node server.js
# 或使用 npm
npm start
```

**服务地址**: `http://localhost:3456`

**运行模式**:
- 首次执行时以守护进程方式后台启动
- 重复启动时会检测端口占用，提供"重新运行"或"显示 URL"选项
- 环境变量 `MD_VIEW_DAEMON=1` 标识守护进程模式

### 1.2 客户端环境

本服务为本地 HTTP API，无需额外 SDK，使用任意 HTTP 客户端即可调用：

| 语言 | 调用方式 | 示例 |
|-----|---------|------|
| JavaScript | `fetch()` | `fetch('http://localhost:3456/api/load', {...})` |
| curl | 命令行 | `curl -X POST http://localhost:3456/api/load -H 'Content-Type: application/json' -d '{...}'` |
| Python | `requests` | `requests.post('http://localhost:3456/api/load', json={...})` |

### 1.3 静态资源

服务同时提供静态文件访问（`md-view/public/` 目录）：

| 资源 | 路径 | 说明 |
|-----|------|------|
| 前端页面 | `http://localhost:3456/` | `md-view/public/index.html` |
| 样式文件 | `http://localhost:3456/style.css` | `md-view/public/style.css` |
| 前端脚本 | `http://localhost:3456/app.js` | `md-view/public/app.js` |

## 2. 调用方式与示例

### 2.1 API 接口列表

本仓库提供以下 HTTP/RESTful API 接口：

#### 2.1.1 POST `/api/select-folder`

弹出系统文件夹选择对话框（仅 Windows 支持）。

**请求**: 无需请求体

**响应示例**:

```json
{
  "path": "D:\\Work\\some-folder"
}
```

或用户取消时：

```json
{
  "cancelled": true
}
```

**错误响应**:

```json
{
  "error": "Folder dialog is only supported on Windows"
}
```

**说明**: 通过 PowerShell 调用 Windows Forms 的 `FolderBrowserDialog`，超时时间 30 秒。

#### 2.1.2 POST `/api/load`

加载指定文件夹，扫描其中的 Markdown 文件并渲染。

**请求体**:

```json
{
  "folderPath": "/path/to/folder",
  "filePath": "/path/to/folder/specific.md"
}
```

| 字段 | 类型 | 必填 | 说明 |
|-----|------|------|------|
| `folderPath` | string | 是 | 要加载的文件夹绝对路径 |
| `filePath` | string | 否 | 指定要加载的具体文件，不传则默认加载第一个 Markdown 文件 |

**响应示例**:

```json
{
  "folderPath": "/path/to/folder",
  "files": [
    { "name": "doc1.md", "fullPath": "/path/to/folder/doc1.md" },
    { "name": "doc2.md", "fullPath": "/path/to/folder/doc2.md" }
  ],
  "currentFile": "/path/to/folder/doc1.md",
  "content": "# Markdown 原始内容...",
  "html": "<h1>Markdown 渲染后的 HTML...</h1>"
}
```

**说明**: 仅扫描 `.md` 和 `.markdown` 后缀文件，使用 `marked` 库进行 Markdown 到 HTML 的转换。代码位置：`md-view/server.js:97-168`

#### 2.1.3 GET `/api/file`

读取指定文件的原始内容和渲染后的 HTML。

**请求参数**:

```
GET /api/file?path=/path/to/file.md
```

| 参数 | 类型 | 必填 | 说明 |
|-----|------|------|------|
| `path` | string | 是 | 文件的绝对路径 |

**响应示例**:

```json
{
  "content": "# Markdown 原始内容...",
  "html": "<h1>Markdown 渲染后的 HTML...</h1>",
  "path": "/path/to/file.md"
}
```

**说明**: 代码位置：`md-view/server.js:171-196`

#### 2.1.4 POST `/api/refresh`

重新读取并渲染指定文件（用于文件内容变更后的刷新）。

**请求体**:

```json
{
  "filePath": "/path/to/file.md"
}
```

| 字段 | 类型 | 必填 | 说明 |
|-----|------|------|------|
| `filePath` | string | 是 | 要刷新的文件绝对路径 |

**响应示例**: 同 `/api/file`

**说明**: 代码位置：`md-view/server.js:199-224`

### 2.2 cURL 调用示例

```bash
# 加载文件夹
curl -X POST http://localhost:3456/api/load \
  -H 'Content-Type: application/json' \
  -d '{"folderPath": "D:/Work/docs", "filePath": "D:/Work/docs/readme.md"}'

# 读取单个文件
curl 'http://localhost:3456/api/file?path=D:/Work/docs/readme.md'

# 刷新文件
curl -X POST http://localhost:3456/api/refresh \
  -H 'Content-Type: application/json' \
  -d '{"filePath": "D:/Work/docs/readme.md"}'
```

### 2.3 JavaScript 调用示例

```javascript
// 加载文件夹
const res = await fetch('http://localhost:3456/api/load', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    folderPath: 'D:/Work/docs',
    filePath: 'D:/Work/docs/readme.md'
  })
});
const data = await res.json();
console.log(data.html); // 渲染后的 HTML
console.log(data.files); // 文件夹中所有 Markdown 文件列表
```

### 2.4 Python 调用示例

```python
import requests

res = requests.post('http://localhost:3456/api/load', json={
    'folderPath': 'D:/Work/docs',
    'filePath': 'D:/Work/docs/readme.md'
})
data = res.json()
print(data['html'])
```

## 3. 认证与授权

### 3.1 认证机制

**本仓库未实现任何认证机制。**

服务默认绑定 `localhost:3456`，仅监听本地回环地址，不接受外部网络访问。这意味着：

- 服务设计为**本地单机工具**，不暴露在网络上
- 无需 API Key、Token 或 OAuth 认证
- 任何能访问本机 loopback 地址的进程均可调用接口

### 3.2 安全注意事项

- 服务通过 `express.static('public')` 公开 `md-view/public/` 目录下的静态文件
- `/api/load`、`/api/file`、`/api/refresh` 接口接受任意文件系统路径，未做路径沙箱限制
- 如需限制访问范围，建议在调用方进行路径校验或通过反向代理添加认证

## 4. 错误处理

### 4.1 统一错误响应结构

所有错误均以标准 HTTP 状态码和 JSON 格式返回：

```json
{
  "error": "错误描述文本"
}
```

### 4.2 常见错误码

| HTTP 状态码 | 错误场景 | 错误描述示例 | 处理建议 |
|-------------|---------|-------------|---------|
| 400 | 缺少必填参数 | `"folderPath is required"` | 检查请求体是否包含必需字段 |
| 400 | 路径不是目录 | `"Path is not a directory: ..."` | 确保传入的是目录路径 |
| 400 | 路径不是文件 | `"Path is not a file: ..."` | 确保传入的是文件路径 |
| 400 | 无效路径 | `"Invalid or non-existent path selected"` | 检查路径是否存在 |
| 404 | 目录不存在 | `"Directory does not exist: ..."` | 检查文件夹路径是否正确 |
| 404 | 文件不存在 | `"File does not exist: ..."` | 检查文件路径是否正确 |
| 500 | 读取目录失败 | `"Failed to read directory: ..."` | 检查目录权限 |
| 500 | 读取文件失败 | `"Failed to read file: ..."` | 检查文件权限或编码 |
| 500 | 文件夹对话框超时 | `"Folder dialog timed out"` | 30 秒内未选择文件夹，重试 |
| 500 | 非 Windows 系统 | `"Folder dialog is only supported on Windows"` | `/api/select-folder` 仅支持 Windows |

### 4.3 端口占用处理

当端口 3456 已被占用时，服务会在控制台提示并等待用户选择：
- 选项 1：结束旧进程并重启
- 选项 2：显示已运行服务的 URL

## 5. 版本管理与兼容性

### 5.1 当前版本

```json
{
  "name": "md-view",
  "version": "1.0.0"
}
```

代码位置：`md-view/package.json`

### 5.2 接口稳定性

本仓库为本地工具，当前版本为 `1.0.0`，接口尚未进行版本化管理。所有 API 路径无前缀版本号（如 `/v1/`）。

**兼容性建议**:
- 当前所有接口均为无版本路径，直接变更可能影响已有调用方
- 建议未来如需破坏性变更，采用 URL 路径版本化：`/v1/load`、`/v2/load`

### 5.3 依赖版本

| 依赖 | 版本 | 用途 |
|-----|------|------|
| express | ^4.18.2 | HTTP 服务框架 |
| marked | ^12.0.0 | Markdown 渲染引擎 |
