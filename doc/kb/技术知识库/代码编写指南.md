## 2. 文件放置规则

> 完整目录树请参考 [仓库概览.md](../仓库概览.md#项目结构)

**新建文件位置规则**：
- 后端服务代码: 放在项目根目录，如 `LightMDKit/server.js`（入口文件直接位于根目录）
- 前端静态资源: 放在 `LightMDKit/public/` 目录下（HTML、CSS、JS）
- 依赖声明: `LightMDKit/package.json` 位于根目录
- 业务数据（Markdown文件）: 存放在外部任意目录，通过 API 动态加载

### 2.1 文件结构

```
LightMDKit/
├── server.js          # Express 服务端入口
├── package.json       # 项目依赖与脚本
├── public/            # 静态资源目录（由 Express 托管）
│   ├── index.html     # 单页应用 HTML 入口
│   ├── app.js         # 前端业务逻辑（IIFE 包裹）
│   └── style.css      # 前端样式表
└── doc/               # 项目文档
```

### 2.2 模块划分

本项目采用前后端分离的轻量架构，无构建工具、无前端框架。

- **服务端（`LightMDKit/server.js`）**：
  - 提供静态文件托管（`express.static`）。
  - 提供 REST API：文件夹选择、文件加载、文件刷新。
  - 进程守护逻辑：端口占用检测、后台进程拉起、旧进程结束。

- **前端（`LightMDKit/public/app.js`）**：
  - 所有业务逻辑封装在单个 IIFE 中，避免全局命名空间污染。
  - 功能按职责划分为：文件夹/文件操作、Markdown 渲染、目录生成、编辑模式、侧边栏交互（折叠/拖拽调整宽度）、历史导航（文档内链接跳转 + 返回上一文档）、文件刷新（重新扫描目录发现新增/删除文件）。

- **样式（`LightMDKit/public/style.css`）**：
  - 与 HTML 结构一一对应，按页面区域分块书写（Toolbar、Sidebar、Content）。

### 2.3 新增文件原则

- 前端无构建步骤，新增脚本直接在 `LightMDKit/public/` 下创建 `.js` 文件，并在 `LightMDKit/index.html` 中通过 `<script src="...">` 引入。
- 若新增服务端接口，直接在 `LightMDKit/server.js` 的 `app.listen` 之前添加路由处理函数。

## 3. 代码分层职责

### 3.1 Server/路由层 (Express)

- **职责**: HTTP 请求处理、参数校验、文件系统操作、Markdown 渲染
- **特点**: 所有路由集中在单一 `LightMDKit/server.js` 文件中，每个路由处理器内完成参数校验、错误处理、响应返回
- **典型方法签名**: `(req, res) => { ... }`（Express 标准路由回调）
- **参考代码**: `LightMDKit/server.js:19-94`（/api/select-folder）、`LightMDKit/server.js:97-168`（/api/load）

### 3.2 前端交互层 (Vanilla JavaScript IIFE)

- **职责**: DOM 操作、用户交互响应、文件 API 调用、Markdown 渲染协调
- **特点**: 使用 IIFE（立即执行函数表达式）封装全局作用域，事件驱动的响应式交互
- **参考代码**: `LightMDKit/public/app.js:1-515`

### 3.3 样式层 (CSS)

- **职责**: 页面布局、主题样式、响应式交互效果
- **特点**: 纯 CSS，采用 GitHub 设计风格（Markdown 渲染使用 github-markdown-css CDN）
- **参考代码**: `LightMDKit/public/style.css:1-315`

### 3.4 守护进程管理

- **职责**: 端口检测、进程管理、后台服务启动
- **特点**: 通过环境变量 `LIGHTMDKIT_DAEMON` 区分前台启动和后台守护模式
- **参考代码**: `LightMDKit/server.js:282-349`

## 5. JavaScript 编写规范

### 5.1 异步处理

- **统一使用 `async/await`**，禁止使用回调地狱。
- File System Access API 的异步操作（如 `showDirectoryPicker`、`getFile`、`createWritable`）必须用 `try...catch` 包裹，并给用户友好的状态提示。

```js
async function selectFolder() {
  try {
    setStatus('等待选择文件夹...');
    const dirHandle = await window.showDirectoryPicker({ mode: 'readwrite' });
    // ...
    setStatus('加载成功', 'success');
  } catch (e) {
    if (e.name === 'AbortError') {
      setStatus('已取消');
    } else {
      setStatus(e.message, 'error');
    }
  }
}
```

### 5.2 DOM 操作

- **DOM 引用集中获取**：在 IIFE 最顶部一次性通过 `document.getElementById` 或 `document.querySelector` 获取所有需要操作的元素。
- **优先使用 `textContent`** 更新文本，避免 `innerHTML` 引入 XSS；仅在需要插入 HTML 结构时使用 `innerHTML`，并确保内容已转义。
- 动态创建元素使用 `document.createElement`，避免拼接 HTML 字符串。

```js
// 集中获取 DOM 引用
const btnRefresh = document.getElementById('btn-refresh');
const statusEl   = document.getElementById('status');

// 安全地更新文本
statusEl.textContent = msg;

// 动态创建元素
const item = document.createElement('a');
item.className = 'toc-item level-' + level;
item.textContent = h.textContent || '';
```

### 5.3 事件绑定

- 简单事件直接通过 `addEventListener` 绑定。
- 事件处理函数使用箭头函数或普通具名函数。
- 对于动态生成的元素（如目录项），在创建时直接绑定事件，不依赖事件委托（除非性能需要）。

```js
// 直接绑定
btnRefresh.addEventListener('click', refreshCurrentFile);

// 箭头函数绑定
btnToggleToc.addEventListener('click', () => {
  sidebar.classList.toggle('collapsed');
});

// 动态元素创建时绑定
item.addEventListener('click', e => {
  e.preventDefault();
  // ...
});
```

### 5.4 状态管理

- 所有状态变量声明在 IIFE 顶部，使用 `let`。
- 状态变更后，及时调用对应的 `updateXxx()` 或 `renderXxx()` 函数同步 UI。

```js
// IIFE 顶部状态声明
let currentFiles = [];
let currentFile = null;
let isEditMode = false;
let fileHistory = [];
```

### 5.5 IIFE 结构模板

```js
(function () {
  // 1. DOM 引用
  const btnXxx = document.getElementById('btn-xxx');

  // 2. 状态变量
  let someState = false;

  // 3. 工具函数
  function helper() { }

  // 4. 业务函数
  async function doSomething() { }

  // 5. 事件绑定

```

### 5.6 装饰器模式：函数增强

项目使用装饰器模式在不修改原函数的情况下增强其行为。典型场景是为已有函数追加额外的副作用（如创建 IntersectionObserver）。

**参考代码**: `LightMDKit/public/app.js:508-512`

```js
const originalRenderToc = renderToc;
renderToc = function () {
  originalRenderToc();
  setupTocObserver();  // 每次渲染 TOC 后重新创建 IntersectionObserver
};
```

这种模式确保了 `renderToc` 的原有逻辑不变，同时在每次调用后自动执行 `setupTocObserver`，实现目录滚动监听功能的无缝集成。

### 5.7 内部链接拦截

项目通过事件委托拦截内容区内的 Markdown 相对链接，实现文件间导航而无需离开页面。

**参考代码**: `LightMDKit/public/app.js:340-358`

```js
contentEl.addEventListener('click', async (e) => {
  const link = e.target.closest('a');
  if (!link) return;
  const href = link.getAttribute('href');
  if (!href) return;
  // 跳过外部链接、锚点、mailto 等
  if (/^(https?:|mailto:|#|\/\/)/i.test(href)) return;
  // 解码并提取文件名
  const fileName = decodeURIComponent(href.replace(/^\.\//, ''));
  const entry = currentFiles.find(f => f.name === fileName);
  if (entry) {
    e.preventDefault();
    // 记录历史并加载新文件
    if (currentFile && currentFile !== fileName) {
      fileHistory.push(currentFile);
      updateBackButton();
    }
    await loadFile(fileName);
  }
});
```

**关键设计点**:
- 使用正则 `/^(https?:|mailto:|#|\/\/)/i` 过滤非相对路径链接
- 通过 `currentFiles` 数组验证目标文件是否存在，避免加载不存在的文件
- 自动维护文件浏览历史栈（`fileHistory`），支持返回操作

### 5.8 状态提示自动消失

`setStatus()` 函数在显示消息 3 秒后自动清除，避免消息长期残留。

**参考代码**: `LightMDKit/public/app.js:32-42`

```js
function setStatus(msg, type = '') {
  statusEl.textContent = msg;
  statusEl.className = 'status ' + type;
  if (!msg) return;
  setTimeout(() => {
    if (statusEl.textContent === msg) {  // 仅当消息未被更新时才清除
      statusEl.textContent = '';
      statusEl.className = 'status';
    }
  }, 3000);
}
```

**关键设计点**:
- 使用 `type` 参数控制状态样式（`''` 默认、`'error'` 错误、`'success'` 成功）
- 通过 `textContent` 比对防止覆盖后续新消息
- 传入空消息时仅更新 DOM，不设置自动清除定时器

## 6. CSS 编写规范

### 6.1 书写顺序

按页面结构自上而下书写：

1. 全局重置（`*`、`html`、`body`）
2. 顶层布局（`.app`、`.main`）

## 7. 错误处理规范

- **错误类型**: 使用 HTTP 状态码 + JSON `{ error: string }` 格式
- **错误传播**: 各层独立处理错误，不在层间抛出自定义 Error 对象；服务端通过 `res.status(code).json({ error: message })` 返回，前端通过 `try/catch` 捕获并调用 `setStatus(message, 'error')` 展示
- **日志记录**: 服务端使用 `console.log`（信息）和 `console.error`（错误），带 `[LightMDKit]` 前缀标识模块
- **参考代码**: `LightMDKit/server.js:73-75`（PowerShell 错误处理）、`LightMDKit/public/app.js:247-254`（前端错误处理）

**错误处理模式示例**:

```javascript
// 服务端：参数校验 + 状态码 + 错误信息
if (!folderPath) {
  return res.status(400).json({ error: 'folderPath is required' });
}

// 前端：try/catch + 状态提示
try {
  await renderFile(entry);
} catch (e) {
  console.error(e);
  setStatus(e.message, 'error');
}
```

## 8. 日志记录规范

- **API**: 使用 Node.js 内置的 `console.log` / `console.error`
- **日志级别**: 
  - `console.log`: 正常流程信息（如 `[LightMDKit] /api/select-folder requested`）
  - `console.error`: 错误信息（如 `PowerShell stderr:...`、`Server error:...`）
- **格式**: 可选模块前缀 `[LightMDKit]` + 描述性文本
- **参考代码**: `LightMDKit/server.js:20`、`LightMDKit/server.js:74`

### 10.3 如何添加新状态

以添加 **"是否显示行号"** 状态为例：

1. **声明状态**：在 IIFE 顶部添加 `let` 声明。

function toggleLineNumbers() {
  showLineNumbers = !showLineNumbers;

### 10.4 如何添加服务端 API

以添加 **获取文件元信息** 接口为例：

1. 在 `LightMDKit/server.js` 中新增路由（放在 `app.listen` 之前）。

```js
// GET /api/file-info - 获取文件元信息
app.get('/api/file-info', (req, res) => {
  const filePath = req.query.path;
  if (!filePath) {
    return res.status(400).json({ error: 'path query parameter is required' });
  }
  const resolvedPath = path.resolve(filePath);
  // ... 校验与读取逻辑 ...
  const stats = fs.statSync(resolvedPath);
  res.json({
    path: resolvedPath,
    size: stats.size,
    mtime: stats.mtime
  });
});
```

2. 前端通过 `fetch` 调用：

```js
async function fetchFileInfo(filePath) {
  const res = await fetch('/api/file-info?path=' + encodeURIComponent(filePath));
  if (!res.ok) throw new Error('Failed to fetch file info');
  return res.json();
}
```

## 11. 文件刷新功能开发指引

### 11.1 功能说明

文件刷新功能允许用户在不重新选择文件夹的情况下，重新扫描目录以发现新增或删除的 Markdown 文件，并重新加载当前文件内容。核心实现在 `LightMDKit/public/app.js:281-335`。

### 11.2 实现要点

1. **文件夹句柄复用**：通过 `currentFolderHandle` 保存用户选择的文件夹句柄，刷新时直接复用，无需重新弹出选择对话框。

2. **重新扫描目录**：

```js
const files = [];
for await (const [name, handle] of currentFolderHandle.entries()) {
  if (handle.kind === 'file') {
    const ext = name.split('.').pop().toLowerCase();
    if (ext === 'md' || ext === 'markdown') {
      files.push({ name, handle });
    }
  }
}
files.sort((a, b) => a.name.localeCompare(b.name));
```

3. **变更检测**：

```js
const oldCount = currentFiles.length;
const wasRemoved = !files.some(f => f.name === currentFile);
currentFiles = files;
const newlyAdded = files.length - oldCount;
```

4. **边界处理**：
   - 当前文件已被删除 -> 显示空状态，停止刷新
   - 发现新文件 -> 提示新增数量
   - 无变化 -> 简单提示"已刷新"

5. **重新渲染**：刷新后调用 `renderFile(entry)` 重新读取并渲染当前文件。

### 11.3 使用示例

```js
async function refreshCurrentFile() {
  if (!currentFile) {
    setStatus('请先加载文件', 'error');
    return;
  }
  if (!currentFolderHandle) {
    setStatus('请先加载文件夹', 'error');
    return;
  }
  setStatus('刷新中...');
  // 重新扫描 -> 检测变更 -> 重新渲染
}

btnRefresh.addEventListener('click', refreshCurrentFile);
```

## 14. 配置文件编写规范

### 14.1 配置文件位置

| 配置类型 | 位置 | 命名格式 |
|---------|------|---------|
| 项目依赖配置 | `LightMDKit/package.json` | `package.json`（npm 标准） |
| 项目锁定配置 | `LightMDKit/package-lock.json` | `package-lock.json`（npm 自动生成） |

### 14.2 配置文件格式

- **文件格式**: JSON
- **缩进**: 2 空格
- **命名风格**: 依赖使用 npm 包名标准（kebab-case）
- **注释风格**: JSON 不支持注释

### 14.3 package.json 配置项

| 配置项 | 类型 | 必填 | 说明 |
|-------|------|------|------|
| name | string | 是 | 项目标识名 |
| version | string | 是 | 语义化版本号 |
| description | string | 否 | 项目描述 |
| main | string | 否 | 入口文件 |
| scripts | object | 否 | npm 脚本命令 |
| dependencies | object | 是 | 运行时依赖 |

**示例**:

```json
{
  "name": "LightMDKit",
  "version": "1.0.0",
  "description": "Local markdown viewer with GitHub style",
  "main": "server.js",
  "scripts": {
    "start": "node server.js"
  },
  "dependencies": {
    "express": "^4.18.2",
    "marked": "^12.0.0"
  }
}
```

### 14.4 环境变量和敏感信息

- **环境变量**: 项目使用 `LIGHTMDKIT_DAEMON` 环境变量控制守护进程模式（值为 `'1'` 表示守护模式）
- **敏感信息**: 本项目为本地工具，不涉及敏感信息

### 14.5 新增/修改配置

**新增依赖步骤**:
1. 运行 `npm install <package-name>` 自动更新 `package.json`
2. 在 `LightMDKit/server.js` 中通过 `require()` 引入新依赖
3. 测试服务启动是否正常

**修改配置注意事项**:
- 修改 `package.json` 后运行 `npm install` 同步依赖
- 不要手动编辑 `package-lock.json`
