# md-view 排障指南

本文档汇总 md-view 项目（Node.js + Express + 浏览器端 File System Access API）在运行与使用过程中可能遇到的常见问题、根因分析与解决方案。

---

## 一、浏览器兼容性问题

### 1.1 File System Access API 不支持

| 项目 | 说明 |
|------|------|
| **现象** | 点击右上角下拉框选择“加载文件夹...”后没有任何反应；或状态栏提示“浏览器不支持文件夹选择，请使用 Chrome 或 Edge”。 |
| **原因** | 浏览器端使用 `window.showDirectoryPicker()` 来选择本地文件夹，该 API 仅在 Chromium 内核浏览器（Chrome、Edge、Opera 等）中受支持。Firefox、Safari 及旧版浏览器不支持此 API。 |
| **解决方案** | 1. 使用 Chrome 或 Microsoft Edge 浏览器访问。<br>2. 确保浏览器版本较新（建议 Chrome 86+ / Edge 86+）。<br>3. 若必须使用其他浏览器，目前无法使用“加载文件夹...”功能，需通过服务端接口或其他方式加载文件。 |

**相关代码**：
- `md-view/public/app.js` 第 208-213 行：`selectFolder()` 函数检测 `window.showDirectoryPicker` 是否存在。

## 二、权限问题

### 2.1 文件夹选择后无法编辑保存

| 项目 | 说明 |
|------|------|
| **现象** | 点击“编辑”按钮可进入编辑模式，修改内容后点击“浏览”切换回浏览模式时，状态栏提示“保存失败: NotAllowedError”或类似权限错误。 |
| **原因** | `window.showDirectoryPicker({ mode: 'readwrite' })` 需要用户授予**读写权限**。部分浏览器在首次弹窗时默认仅授予只读权限，或用户在权限提示中选择了拒绝。 |
| **解决方案** | 1. 重新选择文件夹，在浏览器权限弹窗中确认授予“编辑文件”权限。<br>2. 在浏览器地址栏左侧的权限图标中，检查并授予该网站的文件访问权限。<br>3. 若仍失败，尝试重新启动浏览器后再次选择文件夹。 |

**相关代码**：
- `md-view/public/app.js` 第 216 行：`showDirectoryPicker({ mode: 'readwrite' })`。
- `md-view/public/app.js` 第 371-386 行：`saveCurrentFile()` 通过 `entry.handle.createWritable()` 写入文件。

### 2.2 选择系统级文件夹或受保护目录导致保存失败

| 项目 | 说明 |
|------|------|
| **现象** | 选择“C:\”、“Program Files”等系统目录后，文件列表正常显示，但编辑保存时报错“保存失败: ...”。 |
| **原因** | 操作系统对系统目录、受保护目录（如 Windows 的 Program Files、System32）有严格的写保护策略，即使浏览器授予了权限，操作系统层面仍会拒绝写入。 |
| **解决方案** | 1. 避免选择系统根目录或受保护目录。<br>2. 选择用户目录下的文件夹，如 `C:\Users\<用户名>\Documents\` 或桌面等常规工作目录。<br>3. 确保当前操作系统用户对目标目录具有读写权限。 |

### 2.3 服务端文件夹选择器仅支持 Windows

| 项目 | 说明 |
|------|------|
| **现象** | 在非 Windows 系统（如 macOS、Linux）上调用 `/api/select-folder` 接口时返回 500 错误，提示“Folder dialog is only supported on Windows”。 |
| **原因** | 服务端使用 PowerShell + `System.Windows.Forms.FolderBrowserDialog` 实现系统文件夹选择对话框，仅适用于 Windows 平台。 |
| **解决方案** | 1. 在 Windows 系统上运行服务端。<br>2. 在 macOS/Linux 上使用时，直接通过浏览器端的 File System Access API 选择文件夹（即使用“加载文件夹...”功能），不依赖服务端选择器。 |

**相关代码**：
- `md-view/server.js` 第 21-23 行：平台检测与错误返回。

## 三、渲染问题

### 3.1 Markdown 内容未渲染或显示空白

| 项目 | 说明 |
|------|------|
| **现象** | 选择文件夹后，文件列表出现，但内容区显示空白或“暂无内容，请先加载文件夹”。 |
| **原因** | 1. 目录下没有 `.md` 或 `.markdown` 文件。<br>2. 文件读取过程中发生异常（如文件被占用、编码问题）。<br>3. `marked` 库未正确加载（CDN 加载失败）。 |
| **解决方案** | 1. 确认目标目录中包含 `.md` 或 `.markdown` 后缀的文件。<br>2. 检查浏览器控制台（F12 -> Console）是否有 `marked is not defined` 等错误；如有，检查网络连接或 CDN 可访问性。<br>3. 查看状态栏的错误提示信息。 |

**相关代码**：
- `md-view/public/app.js` 第 223-230 行：扫描目录时仅保留 `ext === 'md' || ext === 'markdown'` 的文件。
- `md-view/public/app.js` 第 198-206 行：`renderFile()` 使用 `marked.parse()` 渲染。

### 3.2 相对路径链接跳转失败

| 项目 | 说明 |
|------|------|
| **现象** | Markdown 中的相对路径链接（如 `[另一篇文档](./other.md)`）点击后无反应，或浏览器直接打开本地文件路径失败。 |
| **原因** | 浏览器安全策略限制直接访问本地文件系统路径。md-view 通过拦截点击事件（`contentEl.addEventListener('click', ...)`）来在同窗口内打开同目录下的 Markdown 文件，但如果链接格式不符合预期（如包含 `../`、绝对路径、URL 编码异常），拦截逻辑会跳过。 |
| **解决方案** | 1. 确保相对链接使用 `./文件名.md` 或直接 `文件名.md` 的格式。<br>2. 避免使用 `../` 跨目录引用（当前实现仅支持同目录文件）。<br>3. 检查文件名与实际文件完全匹配（区分大小写）。 |

**相关代码**：
- `md-view/public/app.js` 第 340-358 行：链接点击拦截逻辑。

## 四、样式问题

### 4.1 侧边栏收起后宽度未变为 40px

| 项目 | 说明 |
|------|------|
| **现象** | 点击收起按钮（`◀`）后，侧边栏未完全收起，仍保持较宽宽度。 |
| **原因** | 用户通过拖动调整了侧边栏宽度，此时 JavaScript 在 `sidebar` 元素上设置了内联样式（`style.width`、`style.minWidth`、`style.maxWidth`）。CSS 类 `.collapsed` 的 `width: 40px` 优先级低于内联样式，导致被覆盖。 |
| **解决方案** | 代码已在收起时清除内联样式（`sidebar.style.width = ''` 等）。若仍遇到此问题：<br>1. 检查浏览器 DevTools -> Elements，确认 `sidebar` 元素上没有残留的内联宽高样式。<br>2. 尝试强制刷新页面（Ctrl + F5）。 |

**相关代码**：
- `md-view/public/app.js` 第 437-447 行：`btnToggleToc` 点击事件处理，收起时清除内联样式。
- `md-view/public/style.css` 第 154-158 行附近：`.sidebar.collapsed` 样式定义。

### 4.2 CSS/JS 更新后浏览器仍显示旧版本

| 项目 | 说明 |
|------|------|
| **现象** | 修改了 `md-view/style.css` 或 `md-view/public/app.js` 后，浏览器页面未体现最新改动。 |
| **原因** | 浏览器缓存了静态资源。 |
| **解决方案** | 1. 项目已在资源引用后附加版本号查询参数（如 `md-view/style.css?v=7`、`md-view/public/app.js?v=7`），更新时修改 `md-view/public/index.html` 中的版本号即可强制浏览器重新加载。<br>2. 用户端可尝试强制刷新（Ctrl + F5）或清除浏览器缓存。<br>3. `md-view/public/index.html` 中已设置 `Cache-Control: no-cache` 等响应头，但部分浏览器仍可能缓存。 |

**相关代码**：
- `md-view/public/index.html` 第 6-8 行：`<meta http-equiv="Cache-Control" ...>`。
- `md-view/public/index.html` 第 11、55 行：带版本号的资源引用。

## 五、性能问题

### 5.1 快速切换文件时目录高亮闪烁或卡顿

| 项目 | 说明 |
|------|------|
| **现象** | 连续快速切换多个文件时，目录（TOC）高亮项频繁跳动，或页面出现短暂卡顿。 |
| **原因** | 每次渲染目录后都会重新创建 `IntersectionObserver` 实例并监听所有标题元素。快速切换文件时，旧的 observer 可能未完全断开，新的 observer 又立即创建，导致回调频繁触发。 |
| **解决方案** | 代码中已使用 `observer.disconnect()` 在重新创建前断开旧实例。若仍感卡顿：<br>1. 避免过于频繁地连续切换文件。<br>2. 检查 Markdown 文件是否包含极大量的标题（如数百个），大文档可考虑拆分。 |

**相关代码**：
- `md-view/public/app.js` 第 493-512 行：`setupTocObserver()` 与 `renderToc` 的包装逻辑。

### 5.2 大文件编辑时滚动定位不准确

| 项目 | 说明 |
|------|------|
| **现象** | 在浏览模式下滚动到某标题，点击“编辑”后，编辑器未准确定位到对应位置。 |
| **原因** | 编辑器滚动定位基于行高计算（`lineHeight`），若实际行高与计算值存在偏差（如字体加载延迟、自定义 CSS 影响），定位会有偏移。 |
| **解决方案** | 1. 确保浏览器字体已完全加载后再进行模式切换。<br>2. 若使用了自定义 CSS 修改了编辑器字体或行高，需同步调整计算逻辑或接受轻微偏差。 |

**相关代码**：
- `md-view/public/app.js` 第 90-95 行：`scrollEditorToOffset()` 基于 `lineHeight` 计算滚动位置。

## 六、交互问题

### 6.1 下拉框选择“加载文件夹...”后需要再次选择

| 项目 | 说明 |
|------|------|
| **现象** | 在下拉框中选择“加载文件夹...”后，下拉框显示恢复为“请先加载文件夹...”，需要再次点击下拉框才能看到新加载的文件列表。 |
| **原因** | 选择“加载文件夹...”是一个操作项而非文件项，代码在处理时会将 `selectedIndex` 重置为 0（占位选项），以等待文件夹加载完成。这是预期行为，但可能给用户造成“需要再选一次”的错觉。 |
| **解决方案** | 正常行为。加载成功后，文件列表会自动填充到下拉框中，用户可直接再次展开下拉框选择具体文件。 |

**相关代码**：
- `md-view/public/app.js` 第 482-490 行：`fileSelect` 的 `change` 事件处理。
- `md-view/public/app.js` 第 159-191 行：`updateFileSelect()` 更新下拉框选项。

### 7.2 PowerShell 文件夹选择器超时

| 项目 | 说明 |
|------|------|
| **现象** | 调用 `/api/select-folder` 接口后长时间无响应，最终返回“Folder dialog timed out”。 |
| **原因** | PowerShell 弹出的系统文件夹选择对话框在 30 秒内未被用户操作（未选择文件夹也未取消），服务端超时主动终止进程。 |
| **解决方案** | 1. 在弹出文件夹选择对话框后及时操作（选择文件夹或点击取消）。<br>2. 若对话框未显示，检查是否有其他窗口遮挡，或 PowerShell 执行策略是否阻止了脚本运行。 |

**相关代码**：
- `md-view/server.js` 第 66-69 行：30 秒超时处理。

## 八、调试方法

### 8.1 浏览器 DevTools 使用要点

1. **打开 Console 面板（F12 -> Console）**
   - 查看 JavaScript 运行时错误，如 `marked is not defined`、`NotAllowedError` 等。
   - 查看代码中通过 `console.error(e)` 输出的异常详情（如 `md-view/public/app.js` 第 251、276、332、382 行）。

2. **打开 Network 面板**
   - 检查 `md-view/public/style.css`、`md-view/public/app.js`、CDN 资源（`marked.min.js`、`github-markdown.min.css`）是否加载成功。
   - 若 CDN 资源失败，可能是网络问题导致 Markdown 无法渲染。

3. **打开 Application / Sources 面板**
   - 在 `md-view/public/app.js` 中设置断点，逐步调试 `selectFolder()`、`saveCurrentFile()`、`toggleEditMode()` 等关键函数。
   - 检查 Local Storage / Session Storage（本项目未使用，但可用于排查其他问题）。

4. **Elements 面板检查样式**
   - 若侧边栏收起异常，选中 `.sidebar` 元素，检查右侧 Styles 中是否有内联样式（element.style）覆盖了 `.collapsed` 类。
   - 检查 `computed` 标签页中的实际宽高值。

### 8.2 服务端调试

1. **查看控制台输出**
   - `md-view/server.js` 在关键位置有 `console.log` 和 `console.error` 输出，如 `/api/select-folder` 被调用时打印 `[md-view] /api/select-folder requested`。
   - PowerShell 错误信息会输出到 `stderr`，可在控制台查看。

2. **接口测试**
   - 使用 `curl` 或 Postman 直接测试服务端接口：
     ```bash
     curl -X POST http://localhost:3456/api/load \
       -H "Content-Type: application/json" \
       -d '{"folderPath": "C:\\Users\\YourName\\Documents"}'
     ```
   - 检查返回的 JSON 中 `files` 列表是否正确。

## 九、日志与错误信息说明

### 9.1 浏览器端状态栏提示

| 提示信息 | 含义 | 处理建议 |
|----------|------|----------|
| `浏览器不支持文件夹选择，请使用 Chrome 或 Edge` | 当前浏览器不支持 `showDirectoryPicker` | 更换为 Chrome/Edge |
| `等待选择文件夹...` | 已触发文件夹选择对话框，等待用户操作 | 在系统弹窗中选择文件夹 |
| `已取消` | 用户点击了取消或关闭对话框（`AbortError`） | 无需处理，重新选择即可 |
| `加载成功` / `文件已加载` / `已刷新` | 操作成功 | 正常状态 |
| `保存失败: ...` | 文件保存时发生错误 | 检查权限、目录是否受保护、磁盘空间 |
| `请先加载文件` | 在未选择文件的情况下点击了编辑/刷新 | 先通过下拉框选择或加载文件夹 |

### 9.2 服务端错误码

| HTTP 状态码 | 场景 | 处理建议 |
|-------------|------|----------|
| `400` | 请求参数缺失或路径不是目录/文件 | 检查请求体中的 `folderPath`、`filePath` 是否有效 |
| `404` | 目录或文件不存在 | 确认路径正确且未被移动/删除 |
| `500` | 读取目录/文件失败、PowerShell 执行失败、非 Windows 系统调用选择器 | 查看服务端控制台错误详情 |

### 9.3 常见 JavaScript 错误

| 错误名称 | 典型场景 | 处理建议 |
|----------|----------|----------|
| `AbortError` | 用户取消文件夹选择对话框 | 正常行为，无需处理 |
| `NotAllowedError` | 未授予文件读写权限 | 重新选择文件夹并授予权限 |
| `SecurityError` | 浏览器安全策略阻止文件访问 | 确保通过 `https` 或 `localhost` 访问 |
| `TypeError: marked is not defined` | CDN 加载失败 | 检查网络连接，确认 `marked.min.js` 可访问 |
