> 详细的业务流程分析请参考 [业务流程详解](./业务流程详解.md)

> **代码位置约定**：本文所有代码位置均以**逻辑项目前缀** `LightMDKit/` 开头（`LightMDKit/` 是项目名，**不对应磁盘上的子目录**，仓库根目录本身就是项目根），格式为 `LightMDKit/文件路径:行号`。
> **阅读约定**：本文只做**广度索引**（流程清单 + 入口 + 异常分支），逐个流程的时序图、代码追踪与数据流转见 [业务流程详解](./业务流程详解.md)。详解收录了本索引 11 个流程中的 10 个（8 个二级章节 + 2 个三级小节：侧边栏视图切换与布局调整、服务启动与端口复用），另有 1 个流程（目录跳转）未展开、仅在本索引列出，详见各流程末尾的「详解」行。

## 流程分类统计

- **文档加载流程**: 3个
- **文档浏览与导航流程**: 4个
- **文档编辑流程**: 2个
- **后台服务流程**: 2个

**总计**: 11 个业务流程（其中 **10 个在《业务流程详解》中有对应章节**：8 个二级章节 + 2 个三级小节「侧边栏视图切换与布局调整」「服务启动与端口复用」；**1 个仅在本索引列出**：目录(TOC)跳转与高亮）

**架构前提**（理解本文的前提）：LightMDKit 是"前端零构建 + 后端仅托管静态资源"的本地工具。**主链路上所有文件读写都走浏览器 File System Access API**（`showDirectoryPicker` / `FileSystemDirectoryHandle` / `createWritable`），**不经过后端**；`LightMDKit/server.js` 只负责启动守护进程、托管 `LightMDKit/public/` 静态资源，以及一组**当前前端已不再调用**的 `/api/*` 兼容接口（见流程 11）。

## 文档加载流程

### 1. 加载文件夹并浏览文档

**所属业务域**: 文档加载
**一句话概述**: 用户选择一个本地目录后，递归扫描其中所有 Markdown 文件并铺开到侧边栏列表，随后自动打开第一个文件（或指定文件）渲染到主区域。
**触发方式**: 点击侧边栏「📁 加载文件夹...」按钮（`#btn-load-folder`，绑定见 `LightMDKit/public/app.js:1439-1441`）
**关键函数**: `selectFolder()` → `loadFolderHandle()` → `collectMarkdownFiles()` → `flattenByDirectory()` → `renderFileList()` → `renderFile(entry)`
**源码位置**: `LightMDKit/public/app.js:759-778`（`selectFolder`）、`LightMDKit/public/app.js:731-756`（`loadFolderHandle`）、`LightMDKit/public/app.js:224-248`（递归扫描）、`LightMDKit/public/app.js:197-219`（目录优先排序）、`LightMDKit/public/app.js:539-607`（文件列表渲染）、`LightMDKit/public/app.js:614-666`（`renderFile`）

**主要异常分支**:
- 浏览器不支持 File System Access API → 状态栏提示「浏览器不支持文件夹选择，请使用 Chrome 或 Edge」，不进入选择流程（`LightMDKit/public/app.js:760-763`）
- 用户取消选择（`AbortError`）→ 提示「已取消」并复位按钮文案（`LightMDKit/public/app.js:770-771`、`763`）
- 目录下无 Markdown 文件 → 列表与主区域均显示空状态，状态栏提示「目录下无 Markdown 文件」（`LightMDKit/public/app.js:744-748`、`539-548`）
- 扫描触顶（深度 > 6 层或累计 > 3000 个文件）→ 静默停止深入而非报错，已扫到的文件照常可用（`LightMDKit/public/app.js:85-86`、`221`）；`node_modules`、`.git`、`dist` 等目录直接跳过（`LightMDKit/public/app.js:88-90`、`234`）
- 文件在加载途中被移走/改名 → 重新取句柄失败时回退原句柄，读取异常由状态栏报错（`LightMDKit/public/app.js:616-628`、`783-786`）

**详解**: [加载文件夹并浏览文档](./业务流程详解.md#加载文件夹并浏览文档)

### 2. 切换与查看文件

**所属业务域**: 文档加载
**一句话概述**: 在侧边栏文件列表中点击任意 Markdown 文件（可先按路径关键字过滤）即可切换查看，同时刷新正文、目录和当前项高亮。
**触发方式**: 点击文件列表项（`#file-list`，`LightMDKit/public/app.js:1162-1166`）或在过滤框输入 / 按 Esc 清空（`#file-filter`，`LightMDKit/public/app.js:1168-1178`）
**关键函数**: `openFileFromList()` → `loadFile()` → `renderFile()`；`renderFileList()`、`updateActiveFileItem()`
**源码位置**: `LightMDKit/public/app.js:528-535`（`openFileFromList`）、`LightMDKit/public/app.js:781-800`（`loadFile`）、`LightMDKit/public/app.js:614-666`（`renderFile`，含渲染、图片解析、目录与高亮）、`LightMDKit/public/app.js:1168-1170`（过滤）、`LightMDKit/public/app.js:1153-1157`（仅切高亮不重建列表）

**主要异常分支**:
- 点击的是当前已打开文件 → 直接返回，不重复加载（`LightMDKit/public/app.js:529`）
- 路径在当前列表中找不到（如文件已被删除）→ `findEntryByPath()` 返回 `null`，静默不做切换（`LightMDKit/public/app.js:783`、`178-186`）
- 过滤无匹配 → 列表显示「没有匹配的文件」（`LightMDKit/public/app.js:559-565`）
- 文件读取失败（权限/被删）→ 状态栏显示错误信息，停留在原文件（`LightMDKit/public/app.js:796-799`）
- 传统模式下处于编辑态时切换文件 → 自动停止自动保存并回到浏览态（`LightMDKit/public/app.js:788-792`）
- 正文中的相对图片路径 → 经 `resolveImages()` 按当前目录句柄逐级解析成 `objectURL`，失败时保留原 `src` 并告警（`LightMDKit/public/app.js:688-727`）

**详解**: [切换与查看文件](./业务流程详解.md#切换与查看文件)

### 3. 刷新目录

**所属业务域**: 文档加载
**一句话概述**: 重新递归扫描当前目录以发现新增/删除的 Markdown 文件，在保留当前打开文件的前提下刷新列表与正文。
**触发方式**: 点击工具栏「刷新」按钮（`#btn-refresh`，绑定见 `LightMDKit/public/app.js:859`）
**关键函数**: `refreshCurrentFile()` → `collectMarkdownFiles()` → `renderFileList()` → `renderFile(entry)`
**源码位置**: `LightMDKit/public/app.js:802-857`、`LightMDKit/public/app.js:224-248`、`LightMDKit/public/app.js:539-607`

**主要异常分支**:
- 尚未打开任何文件 → 提示「请先加载文件」并直接返回（`LightMDKit/public/app.js:803-806`）
- 没有目录句柄（拖入单个文件场景）→ 跳过目录扫描，仅重新读取当前文件内容（`LightMDKit/public/app.js:807-819`）
- 当前文件已被移除 → 列表更新为最新扫描结果，主区域显示「当前文件已被移除」（`LightMDKit/public/app.js:828-837`）
- 重新扫描或读取抛错（目录被拔盘/权限丢失）→ 状态栏显示错误信息（`LightMDKit/public/app.js:853-856`）

**详解**: [刷新目录](./业务流程详解.md#刷新目录)

## 文档浏览与导航流程

### 4. 目录(TOC)跳转与高亮

**所属业务域**: 文档导航
**一句话概述**: 从当前文档的标题树生成目录，点击目录项跳转到对应标题，滚动正文或移动光标时反向高亮当前所在标题。
**触发方式**: 侧栏切到「目录」页签（`LightMDKit/public/app.js:1160`）、点击某个目录项、滚动正文（观察器）、现代模式下移动光标
**关键函数**: `_renderTocCurrentView()`（传统模式，基于渲染后 DOM）、`renderTocFromSource()`（现代模式，基于编辑器原文）、`setupTocObserver()`、`updateActiveTocItemByCursor()`、`jumpToOffset()`
**源码位置**: `LightMDKit/public/app.js:449-499`、`LightMDKit/public/app.js:364-385`、`LightMDKit/public/app.js:1444-1459`、`LightMDKit/public/app.js:388-399`、`LightMDKit/public/app.js:350-361`、`LightMDKit/public/app.js:267-277`（标题 id 生成与去重）

**主要异常分支**:
- 文档没有标题 → 目录区显示「当前文件没有标题目录」（`LightMDKit/public/app.js:368-370`、`457-459`）
- 标题文本重复 → `generateHeadingId()` 自动追加序号去重，保证目录项与正文 id 一一对应，且与 `headingOffsets` 的键同构（`LightMDKit/public/app.js:267-277`、`275-290`、`313-334`）
- 现代模式下正文 DOM 被隐藏且可能过期 → 目录改从编辑器原文实时解析（输入后 300ms 防抖），高亮由光标位置驱动（`LightMDKit/public/app.js:403-412`、`1424-1425`）
- 侧边栏当前不是目录视图 → `renderToc()` 直接返回，避免读文件时把文件列表挤掉（`LightMDKit/public/app.js:1441-1446`）

**详解**: 无独立章节（详解未收录该流程，本索引为唯一出处；传统模式下的目录跳转依赖 `headingOffsets`，该字段在详解中有收录）

### 5. 文档内链接跳转与返回

**所属业务域**: 文档导航
**一句话概述**: 拦截正文里指向本地 Markdown 文件的相对链接，在当前页直接打开目标文档并把来源压入历史栈，「返回」按钮可逐级回退。
**触发方式**: 点击正文中的相对路径链接（`#content` click 委派，`LightMDKit/public/app.js:868-903`）；点击工具栏「← 返回」（`#btn-back`，`LightMDKit/public/app.js:909-914`）
**关键函数**: contentEl click 处理器、`normalizePathForMatch()`、`findEntryByPath()`、`loadFile()`、`updateBackButton()`
**源码位置**: `LightMDKit/public/app.js:868-903`、`LightMDKit/public/app.js:176-190`、`LightMDKit/public/app.js:781-800`、`LightMDKit/public/app.js:905-914`

**主要异常分支**:
- 外部链接 / 页内锚点 `#` / `mailto:` / 协议相对 `//` → 不拦截，交给浏览器默认行为（`LightMDKit/public/app.js:874`）
- 目标文件不在已扫描列表中 → 不拦截，走默认行为（`LightMDKit/public/app.js:893-902`）
- 历史栈为空 → 返回按钮保持 `disabled`，点击无操作（`LightMDKit/public/app.js:906`、`888`）
- 链接含非法 URL 编码 → `decodeURIComponent` 未包 `try/catch`，异常会冒泡为未捕获的 Promise 拒绝（`LightMDKit/public/app.js:865`，详见本文「已知风险」）

**详解**: [文档内链接跳转与返回](./业务流程详解.md#文档内链接跳转与返回)

### 6. 拖放打开文件或文件夹

**所属业务域**: 文档导航
**一句话概述**: 拖入的 `.md` 或文件夹句柄先写入 IndexedDB，再带 `?drop=<id>` 打开新标签页，由新页面取出句柄完成加载，从而绕开"新标签页拿不到拖放句柄"的浏览器限制。
**触发方式**: 把文件/文件夹拖入页面并松开（`dragenter`/`dragover`/`dragleave`/`drop` 监听，`LightMDKit/public/app.js:1357-1386`，浮层见 `LightMDKit/public/index.html:85-87`）
**关键函数**: `handleDroppedItems()`、`matchCurrentFolder()`、`openDropInNewTab()`、`idbPut()`/`idbGet()`、新标签页 `initFromDropParam()`
**源码位置**: `LightMDKit/public/app.js:1315-1355`、`LightMDKit/public/app.js:1282-1290`、`LightMDKit/public/app.js:1304-1313`、`LightMDKit/public/app.js:1222-1252`、`LightMDKit/public/app.js:1389-1437`、`LightMDKit/public/app.js:1255-1274`（过期清理）

**主要异常分支**:
- 拖入非 Markdown 文件 → 忽略；全部被忽略时提示「仅支持拖入 .md / .markdown 文件或文件夹」（`LightMDKit/public/app.js:1336`、`1330-1332`）
- 浏览器不支持 `getAsFileSystemHandle()` → 回退为 `item.getAsFile()` 的 Blob，只能打开单个文件、无法定位其所在目录（`LightMDKit/public/app.js:1322-1335`、`1393-1410`）
- 新标签页被弹窗拦截 → 状态栏给出可点击的「点击打开」兜底链接（`LightMDKit/public/app.js:1311-1312`、`1271-1280`）
- IndexedDB 记录缺失或超过 24h 被清理 → 提示「拖放数据不存在或已过期，请重新拖入文件」（`LightMDKit/public/app.js:1220`、`1377-1380`）；IndexedDB 不可用时清理逻辑静默忽略（`LightMDKit/public/app.js:1273`）
- 新标签页加载抛错 → 状态栏显示「打开拖入内容失败: ...」（`LightMDKit/public/app.js:1433-1436`）

**详解**: [拖放打开文件或文件夹](./业务流程详解.md#拖放打开文件或文件夹)

## 文档编辑流程

### 8. 编辑并保存文档

**所属业务域**: 文档编辑
**一句话概述**: 在「浏览 ↔ 编辑」之间切换，进入编辑时定位到当前视口最上方的标题，点「浏览」时先写盘再重新渲染并恢复之前的滚动位置。
**触发方式**: 点击工具栏「编辑」/「浏览」按钮（`#btn-edit`，绑定见 `LightMDKit/public/app.js:1109`）
**关键函数**: `toggleEditMode()`、`saveCurrentFile()`、`applySurface()`、`getTopVisibleHeadingId()`、`parseHeadingOffsets()`
**源码位置**: `LightMDKit/public/app.js:1042-1107`、`LightMDKit/public/app.js:916-937`、`LightMDKit/public/app.js:961-995`、`LightMDKit/public/app.js:303-315`、`LightMDKit/public/app.js:279-294`

**主要异常分支**:
- 尚未打开文件 → 提示「请先加载文件」并返回（`LightMDKit/public/app.js:1045-1048`）
- 文件句柄不支持 `createWritable`（拖入的单文件、只读来源）→ 提示「当前文件来源不支持写回保存」，但**不会卡在编辑模式**，仍会切回浏览（`LightMDKit/public/app.js:921-925`、`1027-1035`）
- 写入失败（磁盘/权限）→ 状态栏显示「保存失败: ...」并向上抛出（`LightMDKit/public/app.js:932-936`）
- 在现代模式下点击编辑按钮 → 直接返回（现代模式是常驻编辑态，没有浏览/编辑切换）（`LightMDKit/public/app.js:1043-1044`）

**详解**: [编辑并保存文档](./业务流程详解.md#编辑并保存文档)

### 9. 现代模式即时编辑

**所属业务域**: 文档编辑
**一句话概述**: 现代模式把 CodeMirror 常驻展开做 Typora 式即时渲染（隐藏语法标记、无行号、当前行高亮），编辑内容每 3 秒自动落盘，目录与删除线标注随输入防抖刷新。
**触发方式**: 点击工具栏「现代模式」/「传统模式」按钮（`#btn-mode`，`LightMDKit/public/app.js:1111-1115`）；模式偏好写入 `localStorage`，下次打开自动恢复（`LightMDKit/public/app.js:1471-1479`）
**关键函数**: `setMode()`、`applySurface()`、`startAutosave()`/`stopAutosave()`、`saveCurrentFile(true)`、`scheduleLivePreviewRefresh()`、`refreshStrikeMarks()`、`updateActiveTocItemByCursor()`
**源码位置**: `LightMDKit/public/app.js:998-1040`、`LightMDKit/public/app.js:961-995`、`LightMDKit/public/app.js:939-957`、`LightMDKit/public/app.js:403-412`、`LightMDKit/public/app.js:424-448`、`LightMDKit/public/app.js:388-399`

**主要异常分支**:
- CodeMirror 初始化失败 → 拒绝进入现代模式并提示「编辑器未就绪，无法进入现代模式」；启动时若读到现代模式偏好则自动回退传统模式（`LightMDKit/public/app.js:152-155`、`979-982`、`1449-1457`）
- localStorage 不可用 → 模式偏好读取/写入静默回退「传统模式」（`LightMDKit/public/app.js:45-60`）
- 自动保存失败 → 停止定时器，避免每 3 秒重复报错；来源不可写时切换模式不阻塞（`LightMDKit/public/app.js:944-948`、`985-992`）
- 中文文档常见的 `1~100` 范围写法被误判删除线 → 关闭 CM5 内置删除线，仅在 `~~...~~` 上自行标注（`LightMDKit/public/app.js:115`、`412`、`420-444`）
- 现代模式下 Mermaid 代码块只以源码显示（不渲染图表）、编辑/浏览按钮被隐藏（`LightMDKit/public/app.js:670-671`、`963`）——有意的功能取舍

## 后台服务流程

### 10. 后端服务启动与守护进程管理

**所属业务域**: 服务生命周期
**一句话概述**: 启动器先探测 3456 端口，空闲则以 `LIGHTMDKIT_DAEMON=1` 派生分离的守护进程并打开浏览器后自身退出，端口已被占用则直接打开浏览器，实现"免安装双击即用、界面关闭后服务常驻"。
**触发方式**: `node server.js`、`LightMDKit/dist/lightmdkit.exe`（Windows 绿色包）、`LightMDKit/start.bat` / `LightMDKit/start.sh`（含 Node 环境检查与 `npm install` 兜底）
**关键函数**: `main()`、`isPortInUse()`、`spawnDaemon()`、`runDaemon()`、`openBrowser()`
**源码位置**: `LightMDKit/server.js:291-311`（`main`）、`LightMDKit/server.js:251-263`（端口探测）、`LightMDKit/server.js:265-273`（派生守护进程）、`LightMDKit/server.js:275-289`（监听）、`LightMDKit/server.js:233-249`（跨平台打开浏览器）、`LightMDKit/start.bat`、`LightMDKit/start.sh`、`LightMDKit/stop.bat`、`LightMDKit/stop.sh`

**主要异常分支**:
- 端口已被占用 → 视为服务已在运行，直接打开 `http://localhost:3456` 并退出（`LightMDKit/server.js:307-310`）
- 守护进程监听报 `EADDRINUSE` 或其他错误 → 打印错误并 `process.exit(1)`（`LightMDKit/server.js:280-288`）
- 浏览器打开命令失败（无 GUI / 无 `xdg-open`）→ 静默吞掉 `spawn` 的 `error` 事件，服务本身不受影响（`LightMDKit/server.js:247`）
- 守护进程随界面关闭而消失的兜底 → `stop.bat` 用 `taskkill` 结束 `lightmdkit.exe`/`node.exe`，`stop.sh` 用 `pkill -f` 结束进程（注意 `stop.bat` 会杀掉**所有** node.exe）

**详解**: [服务启动与端口复用](./业务流程详解.md#服务启动与端口复用)（详解中作为《服务端 API 渲染链路》下的三级小节收录，只讲启动与端口复用，不涉及 HTTP 接口本身）

### 11. 服务端 API 渲染链路

**所属业务域**: 对外接口
**一句话概述**: Express 提供四个基于文件系统的接口（弹目录框、扫目录、读单文件、刷新重渲染），渲染统一走 `LightMDKit/public/md-render.js`。
**⚠️ 本流程不在主链路上**：前端 `LightMDKit/public/app.js` 内**没有任何** `fetch(` 调用、也没有 `/api/` 字样，这四个接口**当前没有任何 UI 调用方**，全部文件读写都走浏览器 File System Access API。本流程属于**为外部集成保留的兼容接口**（可被脚本、IDE 插件、其他程序调用），排在本索引最后，请勿据此认为主流程会经过服务端。
**触发方式**: HTTP 调用：`POST /api/select-folder`、`POST /api/load`、`GET /api/file`、`POST /api/refresh`
**关键函数**: 四个路由处理器 → `renderMarkdown()`（`LightMDKit/public/md-render.js:166-169`，内部为 `preserveIndent` + `mergeTableCells` + `patchStrikethrough`）
**源码位置**: `LightMDKit/server.js:19-94`、`LightMDKit/server.js:97-168`、`LightMDKit/server.js:171-196`、`LightMDKit/server.js:199-224`、`LightMDKit/public/md-render.js:10-57`（缩进保留）、`LightMDKit/public/md-render.js:72-132`（跨行表格合并）、`LightMDKit/public/md-render.js:143-164`（仅认双波浪线删除线）

**主要异常分支**:
- 非 Windows 平台调用 `/api/select-folder` → 500「Folder dialog is only supported on Windows」（`LightMDKit/server.js:21-23`）
- 系统目录选择框 30s 未返回 → 强杀 PowerShell 子进程并返回 500「Folder dialog timed out」（`LightMDKit/server.js:66-69`）；用户取消 → `{ cancelled: true }`（`LightMDKit/server.js:79-81`）
- 路径不存在 → 404；路径不是目录/不是文件 → 400；目录或文件读取失败 → 500（`LightMDKit/server.js:106-113`、`143-158`、`180-187`）
- 安全边界：接口按 `path.resolve` 后的绝对路径直接读写磁盘，**无任何目录白名单/鉴权**；且 `app.listen(PORT, cb)` 未指定 host（`LightMDKit/server.js:276`），实际监听 `0.0.0.0`/`::` 全部网卡，日志里的 `http://localhost:3456` 只是展示用，**不构成访问限制**——同局域网可直接调用这些接口读取任意文件（`LightMDKit/server.js:11`、`226`、`276`）

**详解**: [服务端 API 渲染链路](./业务流程详解.md#服务端-api-渲染链路)（详解该节开头的「与前端实际链路的关系」专门说明它为何不在主链路上）；四个接口的请求参数与响应结构见 [API 索引](../技术知识库/API索引.md)

## 已知风险（阅读源码时值得注意）

1. ~~**`renderToc` 是隐式全局变量**~~ **已修复**：`LightMDKit/public/app.js:38` 已补 `let renderToc;` 声明，不再落到 `window` 上（该赋值曾因文件无 `'use strict'` 而创建全局变量）。装饰链本身仍要注意：全项目只在文末 `LightMDKit/public/app.js:1463-1468` 赋值一次，别处再写 `renderToc = ...` 会覆盖掉视图守卫。
2. ~~**`decodeURIComponent` 未做保护**~~ **已修复**：正文链接拦截处（`LightMDKit/public/app.js:877-887`）已用 `try/catch` 包住，非法 `%` 编码（如 `a%zz.md`）不再抛 `URIError`，改为按普通链接放行并打印一条 warning。
3. **`/api/*` 无鉴权、不限制目录、且监听全部网卡**：四个接口按传入绝对路径直接读写磁盘（`LightMDKit/server.js:104`、`178`、`206`）；`app.listen(PORT, cb)`（`LightMDKit/server.js:276`）未传 host，等价于绑定 `0.0.0.0`/`::`，因此同局域网内任何人都能通过 `http://<本机IP>:3456/api/file?path=...` 读取该机器上的任意文件（且 `POST /api/select-folder` 会在主机上弹出原生目录选择框）。若要收敛，应改为 `app.listen(PORT, '127.0.0.1', cb)` 并为 `/api/*` 增加目录白名单。
4. **`stop.bat` 会杀掉机器上所有 `node.exe`**（`LightMDKit/stop.bat:4-6`，`taskkill /F /IM node.exe` 无进程筛选），不止 LightMDKit 的守护进程。
5. **服务端 `/api/load` 不递归**：只扫描一层目录（`LightMDKit/server.js:118-127`），与前端 `collectMarkdownFiles` 的递归语义不一致；两套扫描口径目前只在浏览器侧生效，若将来恢复 API 调用需注意。
