# 核心业务领域

> 本文档从用户视角描述服务提供的业务能力，说明用户可以通过本服务完成哪些业务任务。

## 服务定位

### 业务场景

**md-view** 是一款基于浏览器的 Markdown 文档查看器/编辑器服务。用户通过本地启动服务后，在浏览器中加载本地文件夹，即可浏览、编辑、保存本地 Markdown 文档，获得接近 GitHub 在线阅读的体验。

**典型场景**:
1. **项目文档快速浏览**: 开发者加载项目 `docs/` 目录，一站式浏览 README、API 文档、设计文档等全部 Markdown 文件，通过目录导航和文件内链接在文档间快速跳转。
2. **知识库内容维护**: 技术写作者加载知识库根目录，阅读文档后直接切换编辑模式修改内容，保存即时生效，无需额外编辑器。
3. **本地笔记阅读**: 个人用户使用 Markdown 格式记录学习笔记，按文件夹分类存储，通过目录导航和滚动高亮辅助长文阅读。
4. **文档评审与核对**: 产品经理评审 Markdown 格式的 PRD 文档，通过目录跳转、链接跳转、返回功能完成多文档交叉核对，并在编辑模式下记录批注意见。

### 解决的问题

服务帮助用户在不安装重型编辑器（如 VS Code、Typora）的前提下，快速加载本地 Markdown 文件夹，获得结构化的文档浏览体验（目录导航、文件间跳转、滚动高亮），并提供轻量级的编辑-保存-预览闭环。

### 业务价值

为用户提供轻量、免安装、即开即用的 Markdown 文档浏览方案，降低文档阅读和轻量编辑的门槛，提升知识获取效率。

## 核心业务概念

### 业务实体（用户视角）

| 实体名称 | 对用户的含义 | 用户关心的属性 | 示例 |
|---------|-------------|--------------|------|
| 文件夹 | 文档集合的容器，用户加载的本地目录 | 文件夹路径、包含的 Markdown 文件列表 | `D:\Projects\docs\` |
| Markdown 文件 | 用户浏览和编辑的文档单元 | 文件名、文件路径、文件内容、渲染后的 HTML | `README.md` |
| 目录（TOC） | 文档的章节导航结构 | 标题层级（h1~h6）、标题文本、滚动位置 | "一、概述"、"二、API 接口" |
| 浏览历史 | 用户通过文件内链接跳转形成的访问记录 | 历史栈中的文件路径列表（后进先出） | `[README.md -> api.md]` |
| 编辑会话 | 用户进入编辑模式后的修改状态 | 编辑中的文件、修改后的原文内容、光标位置 | 正在编辑 `guide.md` |

### 业务术语（用户视角）

- **加载文件夹**: 用户选择本地文件夹，服务扫描其中所有 `.md` 和 `.markdown` 文件并加载到应用中的操作
- **浏览模式**: 文档以渲染后的 HTML 格式展示，用户阅读文档的默认模式
- **编辑模式**: 文档以 Markdown 原文格式展示在文本编辑区，用户可以直接修改原文
- **目录导航（TOC）**: 根据文档标题（h1~h6）自动生成的侧边栏导航结构
- **文件内链接**: Markdown 文档中指向同文件夹内其他 Markdown 文件的相对路径链接
- **返回**: 用户通过文件内链接跳转后，按历史顺序退回上一个浏览文档的操作

## 业务能力清单

### 核心业务能力

#### 1. 文件夹加载与文档扫描

**用户可以做什么**:
- 选择本地文件夹，加载其中的 Markdown 文件
- 通过下拉框在文件夹内的文件间切换
- 查看文件夹下所有 Markdown 文件的名称列表

**使用场景**:
用户需要浏览某个项目目录或知识库下的全部 Markdown 文档时，通过文件夹加载一次性导入所有文件，无需逐个打开。

**操作示例**:
```
用户目标: 加载项目文档文件夹
操作步骤:
1. 启动 md-view 服务，浏览器自动打开 http://localhost:3456
2. 在工具栏文件下拉框中选择"加载文件夹..."
3. 在弹出的系统文件夹选择对话框中选择目标目录
4. 点击确定
结果: 文件夹下所有 .md/.markdown 文件列出在下拉框中，第一个文件自动打开
```

#### 2. Markdown 文档浏览

**用户可以做什么**:
- 查看渲染后的 Markdown 文档（GitHub 风格样式）
- 通过下拉框切换不同文件
- 通过左侧目录导航跳转到文档的特定章节

**使用场景**:
用户阅读技术文档、API 说明、设计文档等 Markdown 文件，需要清晰的排版和结构化的导航。

**操作示例**:
```
用户目标: 查看 README.md 文档
操作步骤:
1. 加载包含 README.md 的文件夹
2. 从下拉框中选择 README.md（或自动打开第一个文件）
3. 在左侧目录中点击"API 接口"章节
结果: 页面平滑滚动到"API 接口"标题处，文档以 GitHub 风格渲染展示
```

#### 3. Markdown 文档编辑与保存

**用户可以做什么**:
- 点击"编辑"按钮进入编辑模式，查看和修改 Markdown 原文
- 在文本编辑区直接修改文档内容
- 点击"浏览"按钮保存修改并切换回浏览模式

**使用场景**:
用户在阅读文档时发现内容需要修正，或需要在现有文档中添加批注、更新信息。

**操作示例**:
```
用户目标: 修改文档中的过时内容
操作步骤:
1. 浏览到目标文件，阅读至需要修改的章节
2. 点击工具栏"编辑"按钮
3. 光标自动定位到当前章节
4. 在文本编辑区修改 Markdown 原文
5. 点击"浏览"按钮
结果: 修改内容保存到原文件，页面重新渲染，滚动位置恢复
```

#### 4. 文件内链接导航

**用户可以做什么**:
- 点击文档中的相对路径链接（如 `[报告](report.md)`）在当前应用内打开目标文件
- 通过"返回"按钮退回上一个浏览的文件

**使用场景**:
文档之间存在交叉引用关系（如 API 文档引用错误码定义文件），用户需要在关联文档间快速跳转。

**操作示例**:
```
用户目标: 查看接口文档中引用的错误码定义
操作步骤:
1. 在 API 文档中找到"错误码"链接（指向 errors.md）
2. 点击链接
结果: 页面切换到 errors.md 文件，"返回"按钮变为可用
3. 查看完毕后点击"返回"
结果: 页面退回 API 文档
```

### 管理能力

#### 5. 文档刷新

**用户可以做什么**:
- 点击"刷新"按钮重新从磁盘读取当前文件内容

**使用场景**:
文件被外部编辑器（如 VS Code、Notepad++）修改后，用户需要同步最新内容到 md-view 页面。

#### 6. 目录栏管理

**用户可以做什么**:
- 拖动目录栏右侧边框调整宽度（200px ~ 500px）
- 点击箭头按钮收起/展开目录栏

**使用场景**:
用户根据阅读习惯和屏幕空间，调整目录栏的展示方式，获得更舒适的阅读体验。

### 查询能力

本服务不提供独立的数据查询、统计、报表功能。用户通过文件夹加载后，以浏览和搜索文档内容的方式进行信息查询。

## 用户角色和权限

### 角色说明

| 角色名称 | 角色描述 | 可以做什么 | 不能做什么 |
|---------|---------|-----------|-----------|
| 本地用户 | 在本地启动并使用 md-view 服务的用户 | 加载任意本地文件夹、浏览和编辑其中的 Markdown 文件、管理目录导航 | 无应用层权限控制，但受限于操作系统文件访问权限 |

### 权限边界

本服务为本地桌面工具，不设用户认证和权限管理系统。任何能访问 `http://localhost:3456` 的用户都可以使用全部功能。文件访问权限由操作系统的文件系统权限控制，服务本身不对文件访问做额外限制。

## 业务规则（用户需要知道的）

### 使用限制

- **文件格式限制**: 仅支持 `.md` 和 `.markdown` 扩展名的文件，其他类型文件不会被扫描和列出
- **文件夹对话框**: "加载文件夹..."功能通过后端调用系统对话框实现，仅在 Windows 系统上可用；其他操作系统需依赖前端 File System Access API
- **浏览器兼容性**: 文件夹加载的 File System Access API 需要 Chromium 内核浏览器（Chrome、Edge 等）支持
- **服务端口**: 服务固定运行在 `localhost:3456`，端口不可配置
- **单次加载范围**: 每次加载仅扫描指定文件夹的直接子文件，不递归扫描子目录中的 Markdown 文件

### 业务约束

- **文件名唯一性**: 文件夹内不允许同名 Markdown 文件（操作系统文件命名约束）
- **文件路径安全**: 后端 API 对文件路径进行 `path.resolve()` 处理，防止路径穿越攻击
- **编辑模式切换**: 在编辑状态下切换文件会自动保存当前文件并退出编辑模式
- **退出编辑自动保存**: 从编辑模式切换回浏览模式时，修改内容自动写入原文件

### 状态流转（用户视角）

- **文档状态**: 浏览模式 → 编辑模式 → 浏览模式（保存）
- **浏览历史状态**: 空栈 → 点击链接压栈 → 点击返回弹栈
- **目录栏状态**: 展开 → 点击箭头收起 → 点击箭头展开

## 业务边界

### 本服务提供的能力

- 本地 Markdown 文件夹加载和文件列表展示
- Markdown 文档渲染（GitHub 风格样式）
- Markdown 文档编辑、保存、预览
- 文档目录（TOC）自动生成和导航
- 文件内相对路径链接拦截和跳转
- 浏览历史返回功能
- 文件内容刷新
- 目录栏宽度调整和收起/展开

### 不提供的能力

- 不提供用户认证和权限管理
- 不提供远程仓库同步（如 Git 集成）
- 不提供 Markdown 导出功能（如 PDF、HTML 导出）
- 不提供文档搜索功能（全文搜索、关键字搜索）
- 不提供多文件夹同时加载
- 不提供递归子目录扫描
- 不提供图片上传和图床管理
- 不提供协作文档共享

### 与其他服务的协同

本服务为独立运行的本地工具，不依赖其他外部服务。文件存储由用户本地文件系统提供，渲染依赖 `marked.js` 库，样式依赖 `github-markdown-css` 库。
