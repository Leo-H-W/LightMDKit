## 测试规范

### 命名规范

建议采用以下规范：

- **测试文件**: `server.test.js`（与源文件同名 + `.test` 后缀）
- **测试分组**: `describe('API: {接口路径}', () => { ... })`
- **测试用例**: `it('应{预期行为}当{条件}', () => { ... })`
- **否定用例**: `it('应返回 400 当缺少必需参数', () => { ... })`

### 测试结构

推荐使用 **AAA 模式**（Arrange-Act-Assert）：

```javascript
it('应返回 markdown 的 HTML 内容', async () => {
  // Arrange - 准备测试数据
  const fixtureDir = path.join(__dirname, '__fixtures__');

  // Act - 执行被测操作
  const res = await request(app).post('/api/load').send({ folderPath: fixtureDir });

  // Assert - 验证结果
  expect(res.status).toBe(200);
  expect(res.body.html).toContain('<h1>');
});
```

### Mock 原则

- **Mock 外部依赖**: `child_process.spawn`、`fs.readFileSync` 等系统调用
- **不 Mock 业务逻辑**: `marked()` 转换函数应保持真实调用
- **使用 Jest 内置 Mock**: 无需额外安装 Mock 库
- **测试隔离**: 每个测试用例独立，不共享状态
